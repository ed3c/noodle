Constraints:
- Each order is a pipeline of stage groups executed sequentially. Stages within the same group run concurrently.
- Group related stages into one order rather than separate orders.
- Stage `do` values must match a `task_types[].key` from mise, or omit `do` and provide a `prompt` for ad-hoc stages.
- Each `rationale` should cite a specific scheduling rule or principle.
- Do not include `status` or `skill` fields — the loop sets these automatically.

Task types you may schedule:
- adversarial-review: After cook sessions that produce large diffs (200+ lines), implement plan phases, or complete a planning session
- execute: When backlog items with linked plans are ready for implementation
- meditate: Standalone single-stage order after several reflect cycles have accumulated. Expensive — don't over-schedule.
- noodles-issue-execute: Only when the target schedule selects an authorized ed3c/noodle Issue
- oops: When infrastructure failures are detected (build breaks, test failures, stale Noodle state)
- plan: When backlog items are tagged #needs_plan and have no linked plan yet
- quality: Follow-up stage after execute. Cross-provider review preferred — if codex executed, schedule quality on claude; if claude executed, schedule on codex.
- reflect: Follow-up stage after quality — capture learnings from the completed execute→quality cycle.
