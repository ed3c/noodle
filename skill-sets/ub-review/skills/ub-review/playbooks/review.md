# Candidate product review

Use this playbook only with this set's `SKILL.md` and an original admitted review
role. The original task supplies the candidate, accepted scope, functional
acceptance, selected controls and result locations. Preserve their identities.

Read the original candidate and applicable evidence. Apply the review contract
to findings and the necessity of further observations. Do not implement fixes.
Return source-bound findings, exclusions, unknowns and the original continuation.
If the candidate is not ready, return its missing prerequisite; do not start
the quality tools or replace the Poteto implementation role.

When the admitted role authorizes quality execution, preserve the tools' raw
JSON/EDN/text outputs and UML IR under `$NOODLE_SESSION_DIR/ub-review/`.
Use the original runtime-supplied session directory. The supervisor returns it
in its existing session archive. Do not invent a Host path or copy credentials.
Keep quality execution in the authorized isolated copy. A returned artifact
does not prove the tool ran correctly or that a threshold passed.

The role's write paths remain within the original admission. Tool-generated
mutation/coverage files need an explicitly permitted isolated copy and output
area. An empty product write scope does not authorize arbitrary filesystem work.
Do not create those permissions from this playbook. Unknown effects require
original readback before any retry. Candidate acceptance remains with its owner.
